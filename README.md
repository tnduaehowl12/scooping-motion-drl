# 아이스크림 스쿠핑 모션 (Doosan M0609 · DRL)

협동로봇이 **힘 센서만으로 아이스크림 표면을 찾아 들어가** 회전 성형으로 한 스쿱을 떠서
컵에 붓는 모션 스크립트입니다.

ROKEY 9기 협동 프로젝트 1(Roskin Robbins, 4인)에서 제가 담당한 **로봇 모션 설계** 산출물입니다.
팀 저장소에는 통합 코드가 올라가 있고, 이 저장소는 모션 스크립트 자체와 그 반복 과정을 남긴 것입니다.

- 팀 저장소(원본): https://github.com/Taegyu-Lee1117/Roskin_Robbins
- 실행 환경: **Doosan DART Platform** · DRL (Doosan Robot Language) · M0609 + 스쿱 엔드이펙터

---

## 무엇을 하는 스크립트인가

아이스크림은 **표면 높이가 매번 다르고, 떠낸 자리만큼 패입니다.** 좌표를 고정하면
허공을 긁거나 통 바닥을 찍습니다. 그래서 높이를 미리 정하지 않고 **힘으로 찾습니다.**

```
HOME
  │
  ├─ 1. baseline 측정        정지 상태에서 5회 샘플링 → 힘 센서 영점
  │
  ├─ 2. 표면 탐색            Z = 135mm 에서 2mm 씩 하강,
  │                          baseline 대비 ΔF ≥ 2N 이 2회 연속이면 표면 접촉
  │                          Z = 95mm (통 바닥 추정 + 마진) 는 절대 하한
  │
  ├─ 3. 추가 진입            접촉점에서 7mm 더 눌러 재료를 문다
  │                          ΔF ≥ 2.5N 이면 바닥 긁힘으로 보고 중단
  │
  ├─ 4. 자세 수직화          기울어 들어간 스쿱을 세운다
  │
  ├─ 5. 회전 성형            J6 를 360° 돌려 구(sphere) 모양을 만든다
  │
  ├─ 6. 퍼올리기 (CURL)      X 를 20mm 뒤로 빼면서 자세를 82° 회전
  │                          — Z 는 회전 내내 고정
  │
  ├─ 7. 후퇴·상승            회전이 끝난 뒤에만 120mm 상승
  │
  └─ 8. 붓기                 컵 위로 이동해 쏟는다
```

진입 중 어느 단계든 **ΔF ≥ 12N** 이면 비상 정지합니다.

### 힘 감지 진입 판정

모든 임계값은 **절대값이 아니라 baseline 대비 델타**입니다.
처음에는 절대 힘으로 판정했는데, 자세가 바뀌면 중력이 센서 축에 실리는 양이 달라져
같은 접촉이 다른 숫자로 읽혔습니다. 정지 상태에서 영점을 다시 잡고 그 차이만 보도록 바꿨습니다.

| 판정 | 임계값 | 근거 |
|---|---|---|
| 표면 접촉 | ΔF ≥ 2.0 N, 2회 연속 | 실측 접촉 시 X/Z 축 2~3 N |
| 바닥 긁힘 | ΔF ≥ 2.5 N (추가 진입 중) | 5.0 N 으로는 긁은 뒤에 멈췄다 |
| 비상 정지 | ΔF ≥ 12.0 N | 바닥 접촉이 5~9 N 이므로 그 위로 |

노이즈를 보고 임계값을 자동으로 올리는 로직이 한동안 있었는데,
그게 임계값을 밀어올려 **감지를 아예 막고 있었습니다.** 지워야 동작했습니다.

## 이 저장소의 위치 — 개발 과정판입니다

여기 있는 스크립트는 **DART Platform 에서 모션을 잡아 가던 개발 과정판(v1~v7)** 입니다.
**최종 시연에 올라간 것은 팀 저장소의 ROS 2 패키지**
[`icecream_pj`](https://github.com/tnduaehowl12/roskin-robbins/tree/main/src/icecream_pj)
이고, 거기서 임계값이 다시 조정됐습니다.

| | 이 저장소 `scoop_sphere_v7.py` | 최종 `icecream_pj/motion_config.py` |
|---|---|---|
| 하강 간격 | `PROBE_STEP = 2.0` (2 mm) | `ENTRY_Z_STEP = 1.0` (**1 mm**) |
| 접촉 판정 (Δ) | `F_ENTRY_DELTA = 2.0` | `F_ENTRY_DELTA = 1.3` |
| 중간 하드리밋 (Δ) | 없음 | `F_ENTRY_HARD_LIMIT_DELTA = 15.0` |
| 비상정지 | `F_HARD_DELTA = 12.0` — **변화량** 기준 | `F_EMERGENCY_LIMIT = 40.0` — **절대값** 기준 (`abs(Fx/Fy/Fz)`) |
| 연속 충족 | `CONSEC_HIT_NEEDED = 2` | `ENTRY_CONSEC_HIT_NEEDED = 2` |

**포트폴리오와 발표자료의 수치(1.3 / 15 / 40 N · 1 mm)는 최종판 기준입니다.**
여기 있는 값은 그 전 단계의 것이니, 둘이 다르다고 어느 한쪽이 틀린 것은 아닙니다.

시간순으로도 그렇습니다 — 이 저장소의 `scoop_sphere_v7.py` 가 **2026-08-26**,
팀 저장소의 `icecream_pj` 패키지가 **2026-08-30** 입니다. 뒤엣것이 최종판입니다.
v7 안에는 그 이식을 미리 염두에 둔 주석도 남아 있습니다:

```python
"""X,Z 힘 합성 크기. (ROS2 이식 시 sqrt 대신 제곱값 비교로 변경할 것)"""
```

판정 구조 자체도 바뀌었습니다. 최종판은 안전장치가 **셋**입니다 —
접촉(1.3 N) · 중간 하드리밋(15 N) · 비상정지(40 N 절대값). 앞의 둘은 기준값 대비
변화량이고, 마지막 하나만 절대값입니다. 이 저장소의 v7 은 변화량 둘뿐입니다.

## v1 → v7 에서 고친 것

각 스크립트 머리에 변경 이력을 주석으로 남겨 뒀습니다. 큰 줄기만 적으면

- **[A~D]** 힘 판정을 절대값 → baseline 델타 기반으로 전면 교체, baseline 다중 샘플링
- **[C]** 상승을 분할하고 `movejx` 로 복귀 — `2.1206 NOT REACHABLE` 대응
- **[E]** 퍼올리기에서 `movej(J5)` 금지. TCP 가 반경 210mm 호를 그려 통 벽에 부딪혔습니다
- **[M]** 비상 정지 임계값 5 N → 12 N. 바닥 접촉(5~9 N)보다 낮아서 오작동했습니다
- **[P]** 노이즈 자동 상향 삭제 (위에 적은 그 문제)
- **[T]** 퍼올리기를 제자리 회전 → 기록 모션의 CURL 시퀀스로 교체.
  제자리 회전은 스쿱이 재료를 **밀고 지나가며 쏟아냈습니다.** 끌어담으려면 X 가 뒤로 빠져야 합니다
- **[U]** 바닥 긁힘 대응 — 추가 진입 12mm → 7mm, 긁힘 임계 5.0 → 2.5 N
- **[V]** 탐색 시작 높이 135mm 확정

## 실행 전 확인

- **스쿱을 장착한 상태로** 실행하세요. TCP 가 스쿱 끝 기준으로 잡혀 있습니다
- `PROBE_MIN_Z = 95.0` 은 통 바닥 추정치입니다. 실측 바닥 Z 를 알면 **그 값 + 8** 로 바꾸세요
- 좌표는 저희 작업 셋업의 실측값입니다. 통·컵 위치가 다르면 `HOME_POSX`,
  `POUR_TARGET_POSX`, 레인 진입 지점을 다시 잡아야 합니다
